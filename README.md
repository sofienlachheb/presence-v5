# تقسيم ملف presence v2

## التركيب
1. احتفظ بنسخة احتياطية من ملف src/App1.tsx الحالي.
2. انسخ مجلد src/presence كاملاً من هذه الحزمة إلى مشروع presence v2 داخل src.
3. استبدل src/App1.tsx بالملف الموجود في هذه الحزمة.
4. إذا كان مشروعك يستورد App.tsx بدلاً من App1.tsx، احفظ ملف الدخول المرفق باسم App.tsx بدلاً من App1.tsx. لا حاجة لتغيير استيراد main.tsx حينها.
5. شغّل أمر التطوير أو البناء المعتاد في مشروعك.

## البنية
- src/App1.tsx: ملف الدخول، يستورد التنسيقات ويصدّر التطبيق افتراضياً.
- src/presence/App.tsx: حالة التطبيق الرئيسية وربط الشاشات.
- src/presence/shared.tsx: البيانات الثابتة ودوال التهيئة والمساعدة المشتركة.
- بقية ملفات src/presence: ملف مستقل لكل مكوّن، مثل Dashboard وAttendanceView وStudentsView وSmartAnalyticsCenter.

## الملفات والمتطلبات الموجودة في مشروعك
تستعمل الحزمة ملفات المشروع الأصلية التالية، ولا تتضمن نسخاً بديلة منها:
- src/supabaseClient
- src/styles/pagination.css
- src/styles/Attendance extra.css
- src/styles/GlobalStyles.css
- src/assets/school-logo.png

وتحتاج الحزم الموجودة أصلاً في الكود: react وlucide-react وrecharts وxlsx، بالإضافة إلى متطلبات supabaseClient.

## التحقق
- تم الحفاظ على 66 تعريفاً من الملف الأصلي حرفياً، باستثناء إضافة أو تعديل export.
- تم التحقق من الصياغة وتحويل TypeScript/JSX لكل الوحدات الأربعين.
- تم التحقق من مسارات الوحدات الداخلية وعدم وجود اعتماد دائري.
- أكبر ملف ناتج يبلغ 152011 بايت، أقل من حد Babel البالغ 500KB.
- هذا التحذير من Babel يتعلق بتنسيق الكود المولّد؛ ليس خطأً في وظائف التطبيق.
- لم يتم تشغيل التطبيق أو اختبار الاتصال بقاعدة البيانات، لأن المرفق يتضمن ملف التطبيق فقط دون بقية مشروع presence v2 أو إعداده.
- التقسيم لا يضيف تحميلًا كسولًا ولا يضمن تقليل حجم حزمة الإنتاج.

تفاصيل أحجام الملفات ونتائج التحقق موجودة في verification.json.

## المرحلة 20: نقاط الحصة والتعزيز
- شاشة مستقلة للمدرس تعرض الصفوف والشعب المسندة إليه، مع اختيار الحصة والمادة.
- تعزيز +1/+2/+3 أو نجمة بقيمة +1، وسبب وملاحظة اختياريان، دون ربط بالتقييم أو المخالفات.
- سجل اليوم، سجل الطالب لفترات 1/7/30 يومًا، إحصائيات آخر 7 أيام، وتنبيه لغياب التعزيز خلال 14 يومًا. كل المؤشرات تخص عمليات المدرس الحالي، والتاريخ بتوقيت قطر.
- التراجع يلغي آخر عملية فعالة للمدرس في اليوم الحالي ويحفظ أثرها في سجل الطالب.
- قبل الاستخدام: طبّق `supabase/migrations/20260909_phase20_lesson_points.sql` في محرر SQL لمشروع Supabase. يعتمد الترحيل على الجداول الحالية profiles وstudents وteacher_classes وperiods، ولا يعدل بيانات التقييمات السابقة.
- الترحيل يفعّل RLS ويمنع الإضافة خارج الصفوف المسندة والتعديل والحذف المباشر. لم يُطبّق تلقائيًا على قاعدة البيانات الحية.
- اختبار القبول بعد الترحيل: ادخل بحساب مدرس، اختر صفًا وحصة ومادة، امنح نقطة ثم أعد تحميل الصفحة؛ تحقق من السجل والمجموع، تراجع وأعد التحميل؛ تحقق بحساب مدرس آخر من عزل السجلات ومن رفض إضافة لطالب غير مسند إليه عبر API.
- الشارات وإشعارات ولي الأمر والنقاط السلبية مؤجلة للمرحلة التالية.
- نتيجة التحقق المحلي: فحص TypeScript لم يُظهر أخطاء في LessonPointsView.tsx، لكن `npm run build` يتوقف عند أخطاء في ملفات أخرى موجودة بالمشروع. لا تُعد صلاحيات SQL أو الحفظ متحققًا منهما قبل تطبيق الترحيل وتنفيذ اختبار القبول أعلاه.
